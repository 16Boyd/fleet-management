# Official software sources

**Baseline checked 2026-10-03.** Recheck these official sources at invocation. These are source pointers and package names, not commands to stream remote code into a shell. Resolve exact versions and integrity metadata before asking for the post-container install approval.

| Tool | Official source and installation route | Verification / constraints |
|---|---|---|
| T3Code headless | [Install guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/install.md); upstream installer URL: `https://t3.codes/install.sh`. Review [background service guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/background-service.md). | `t3 --help`, `t3 service status`. Run as `t3code`; inspect and pin the installed release/artifact and verify loopback-only service configuration before starting. Do not run `t3 connect` or log in. |
| Codex CLI | [OpenAI Codex CLI docs](https://developers.openai.com/codex/cli); documented npm package: `@openai/codex`. | Resolve an exact package version and registry integrity; install as `t3code`; verify `codex --version`. Do not start an interactive session or log in. |
| Claude Code CLI | [Quickstart](https://docs.anthropic.com/en/docs/claude-code/quickstart) and [setup](https://docs.anthropic.com/en/docs/claude-code/setup); upstream installer URL: `https://claude.ai/install.sh`. | Stage/hash/inspect the exact installer and its executable download chain. Verify `claude --version`. Recheck supported Debian release and architecture; baseline docs support Debian 10+ on x64/arm64. Do not log in. |
| OpenCode CLI | [OpenCode docs](https://opencode.ai/docs/) and [CLI](https://opencode.ai/docs/cli/); documented npm package: `opencode-ai`. | Resolve exact package version and registry integrity; verify `opencode --version`. Check current platform support. Do not launch the interactive TUI or log in. |
| NVM and Node | [NVM README](https://github.com/nvm-sh/nvm/blob/master/README.md) and [Node.js package-manager guidance](https://nodejs.org/en/download/package-manager/all). Pin a current NVM release and exact Node LTS release using current official instructions. | Stage/hash/inspect the NVM installer and dependencies. Verify Node's official checksum/signature before install; report the exact version. Load NVM in a fresh `t3code` shell; verify `command -v nvm`, `nvm --version`, `node --version`, and `npm --version`. NVM is per-user and a shell function. |
| PNPM | [PNPM installation](https://pnpm.io/installation); the official docs describe npm installation as well as a standalone script. | Python | [Debian stable python3 package](https://packages.debian.org/stable/python3) and [Python on Unix](https://docs.python.org/3/using/unix.html). Use Debian packages `python3`, `python3-venv`, and `python3-pip`. | Resolve exact package versions from signed Debian repository metadata before approval; verify `python3 --version`. Use virtual environments for Python packages and do not install into Debian's system Python with `sudo pip`. |
| Google clasp | [Apps Script clasp guide](https://developers.google.com/apps-script/guides/clasp); npm package: `@google/clasp`. | Check current Node requirement (baseline: Node 20+); resolve exact npm version/integrity and verify `clasp --version`. Do not run `clasp login`. |
| Vercel CLI | [Vercel CLI docs](https://vercel.com/docs/cli); npm package: `vercel`. | Resolve exact npm version/integrity and verify `vercel --version`. Do not run login, `whoami`, or deploy commands. |

For npm CLIs, `npm install -g <package>@<exact-version>` is supported when run as `t3code`, not root. NPM checks registry SRI for fetched tarballs; disclose if transitive dependency versions cannot be pinned before install, and obtain informed approval before running lifecycle scripts. Do not proceed on an integrity mismatch. For vendor shell installers, download locally to a private temporary directory, check official signatures/checksums when available, inspect and hash exact bytes, and transfer/execute only after approval. If the vendor publishes no authenticity metadata, explain that SHA-256 identifies bytes but does not authenticate origin and obtain approval for those exact files.

Never sign in, provide provider/API tokens, deploy, or start an interactive CLI/TUI during setup. If any official installer requires sign-in or unsupported architecture, leave it unrun and report the blocker.
